A bucket holds only sample count, frame rate and how many samples looked degraded or offline, so nothing footage-derived is stored; the file is capped at 8 MB, 200 cameras and 50 incidents per camera, and a truncated or corrupt file is dropped rather than raising. `GET /api/fork/camera_history?range=1h\|6h\|24h\|7d` aggregates the buckets into 12 to 28 cells and is filtered to the caller's allowed cameras, read off the event loop through `asyncio.to_thread`. It is gated by `allow_any_authenticated`, like `/stats`, which means its path also joins `EXEMPT_PATHS` in `frigate/api/auth.py`; without that the global admin check would win and a viewer could not open the Health tab. The tab itself moved from a card grid to a sorted table (state, camera, frame rate, uptime, detector share, issues) with a range selector in the page header beside "last refreshed", a "needs attention" scope, a one-line summary naming the worst cameras first, and per-row sparklines; the sorted column reads brighter than the rest, and clicking anywhere on a row, not just its name, opens a drawer with the cell strip of when the camera was down, the incident log with its reason, and every metric, reason and note the old card showed. The drawer says a whole-hour cell in hours ("1 cell = 1 hour", "6 hours") rather than 60 or 360 minutes, and rounds its "time down" the way the row's badge does, so a sub-minute outage cannot read as "1 min" in the table and "0 min" in the drawer. Range, scope and the open camera live in the URL, so a view survives reload and the back button. The open camera is `?health=<name>`, not the System-wide `?camera=`: that one is a view selection other tabs carry and shared links arrive with, so reading it here put a modal drawer over the page header the moment such a link landed on Health, which is how it first broke the ingress and clipboard specs. The drawer turns off the sheet's own history entry: the URL already carries which camera is open, so letting the sheet push too would take two back presses to leave the tab. The System header row also lost `h-full` from its title and version: the class resolved against the row's own height, so the first time that row wrapped the wrapped line drew over the tab below. Two things the design draws have no backend to sit on and were left out deliberately: a per-camera Restart button (Frigate only restarts the whole service, so the third drawer action opens that camera's settings instead) and a per-incident link into the logs filtered to the camera (the Logs page takes no service or query parameter, so the footer's single "View logs" is as specific as it can honestly be). 37 backend unit tests, 16 vitest cases and 16 e2e specs across desktop and phone.
